# lhg-lr-cite：引用格式规范与核对

> 目标：让引用格式从"最后突击改"变成"写作时就对"。
> 核心纪律：**一种引用制贯穿全文；文内每一个编号在文末都有条目，文末每一条目在文内都被引用过。**

## 1. 何时使用

- 开始写正文前 → 先定引用制（第 3 节二选一）
- 每写完一节 → 跑第 6 节的"节级核对"
- 交稿前 → 跑插件审计脚本 + 第 6 节"终稿核对"

## 2. 输入与输出

**输入**：稿件目录（含正文 md）+ 选定的引用制（gb7714 / apa）。

**输出**：`自查报告-YYYYMMDD.md`（审计脚本结果 + 人工抽查记录 + 豁免清单），结论"通过 / 不通过"。

## 3. 分步方法论

### 3.1 先选引用制（全文统一，二选一）

- **GB/T 7714 顺序编码制**（国内硕博论文默认）：文内用 `[1]` `[2,5]` `[3-7]`，文末按引用顺序编号。适合中文学位论文。
- **GB/T 7714 著者-出版年制**：文内用"（张三，2024）"，文末按著者字母/笔画排序。适合部分期刊。
- **APA 第 7 版**：文内用"（Zhang, 2024）"，文末按字母排序，期刊名与卷号斜体（纯文本稿用文字说明）。

选定后全文不许混用——混用是脚本 CITE-007 抓的第一类问题，也是评审最反感的错误之一。

### 3.2 GB/T 7714 著录四要素（缺一不可）

每条文末条目必须回答四个问题，缺一个就是 blocker：

1. **谁写的**（主要责任者）：`[1] 张三，李四，王五. …`——著者不超过 3 人全列，超过 3 人列前 3 加"，等"。西文著者"姓全大写/首字母大写，名缩写"，如 `Smith J, Lee K.`
2. **哪一年**（出版年）：紧跟在题名/出处之后，如 `…软件学报，2024，35(2)：…`
3. **是什么**（文献类型标识）：`[J]` 期刊、`[M]` 专著、`[D]` 学位论文、`[C]` 会议、`[N]` 报纸、`[EB/OL]` 网络文献。标识缺失 → warning。
4. **从哪来**（出处）：期刊名 + 卷期页码，或出版社 + 出版地。

著录示例（顺序编码制）：
`[1] 刘洪光. 智能体技能设计的方法论研究[J]. 软件学报，2024，35(2)：100-115.`
`[2] 张三，李四，王五，等. 教育评价技术手册[M]. 北京：科学出版社，2023.`

### 3.3 APA 第 7 版要点（中文稿投英文刊常用）

- 文内：`(Zhang, 2024)`、`(Zhang & Li, 2024)`、`(Zhang et al., 2024)`（3 人以上用 et al.）
- 文末：`Zhang, S. (2024). Title of article. Journal Name, 35(2), 100–115.`
- 期刊名与卷号斜体；DOI 能给就给（`https://doi.org/…`）
- 中文文献按拼音转写著者，题名可附英文翻译（方括号）

### 3.4 写作时的引用习惯（防患于未然）

1. 写一节，引用编号当场标，不许"先写完再补编号"——补的一定对不上
2. 转述同一观点引用 2~3 篇即可，堆 8 个编号是"虚胖"
3. 关键定义/论断直接引用（加引号）不超过全文 3 处，且注明页码
4. 网络文献（`[EB/OL]`）必须写引用日期，链接交稿前逐一点击验证有效

### 3.5 跑确定性审计（机器先行）

在稿件目录执行插件自带的两个脚本：

```
python3 <插件目录>/scripts/audit/citation_audit.py  --target <稿件目录>
python3 <插件目录>/scripts/audit/structure_audit.py --target <稿件目录>
```

- blocker：孤儿引用（文内有号文末无条）、僵尸条目（文末有条文内未引）、缺主要责任者、缺年份、缺引言、缺批判性述评——必须清零
- warning：编号不连续、混用引用制、重复著录、缺文献类型标识、缺展望、缺方法说明——修或写豁免
- 有 blocker 时脚本非零退出，供提交前 hook 拦截用

### 3.6 人工核对（机器做不到的）

1. **节级核对**（每节写完）：抽该节 3 条引用，确认编号与文献池一致
2. **终稿抽查**：随机抽 5 条文内引用核对转述忠实度；抽 3 条参考文献核对著录与真实出版信息一致（防编造）
3. **通读批判节**：确认是真批判不是套话（见 lhg-lr-write 第 3.3 节黑名单）
4. **格式目检**：标点全角半角统一、"等"与"et al."不混用、卷期页码格式统一

### 3.7 GB/T 7714 与 APA 对照速查表

| 项目 | GB/T 7714（顺序编码制） | APA 第 7 版 |
|---|---|---|
| 文内 | `[1]`、`[2,5]`、`[3-7]` | `(Zhang, 2024)`、`(Zhang & Li, 2024)` |
| 文末排序 | 按引用顺序编号 | 按著者字母顺序 |
| 著者 3 人以上 | 列前 3 人加"，等" | 列前 20 人，超 20 人用省略号（中文稿一般转写后列前 3 加 et al. 需与期刊确认） |
| 期刊著录 | `软件学报，2024，35(2)：100-115` | `Journal Name, 35(2), 100–115`（期刊名卷号斜体） |
| 专著著录 | `[M]. 北京：科学出版社，2023` | `Publisher. (2023).`（出版地 APA 7 已省略） |
| DOI | 可选 | 尽量给 `https://doi.org/…` |

**注意**：表格是速查不是全文，投稿前务必对照目标期刊的"投稿须知"，期刊常有自定微调。

### 3.8 著录常见错误 Top 8

1. 著者超过 3 人全列出来（应前 3 +"，等"）
2. 西文著者"名在前姓在后"（应姓前名后缩写）
3. 期刊卷期写成"第 35 卷第 2 期"（应 `35(2)`）
4. 页码只写起始页（应写起止 `100-115`）
5. 网络文献不写引用日期
6. 学位论文缺授予单位（`[D]. 北京：北京大学` 不能省后半）
7. 同一著者多篇文献年份后不加 a/b 区分（APA 制：`(Zhang, 2024a)`）
8. 文末条目按著者排序却用了顺序编码制编号（两制混搭，脚本 CITE-007 抓的就是这类）

### 3.9 交稿前 24 小时清单

1. 跑两遍审计脚本，blocker 清零（`citation_audit.py` + `structure_audit.py`）
2. 引用制全文统一（页眉页脚、图表注、附录都不许混用）
3. 文内编号与文末条目双向对应（脚本已查，人工再抽 5+3）
4. 网络文献链接逐一点击，失效的补存档或删除
5. 术语译名全文统一（建术语表对照）
6. 图表编号连续，图表标题格式统一
7. 通读一遍，只找错别字和语病（这遍不许改内容）
8. 把稿件放一晚，第二天只读引言和批判节——如果自己都觉得"没观点"，评审一定也这么觉得

**最后的话**：格式问题是"可修复的错误"，编造与抄袭是"不可修复的污点"。交稿前把力气花在核对真实性上，而不是调行距上。

## 4. 反模式

- ❌ 文末参考文献从别处复制粘贴——十有八九有僵尸条目和错号
- ❌ 为凑引用数量堆编号——评审会抽查，堆出来的引用最经不起查
- ❌ 直接引用大段原文不加引号——这是抄袭，不是引用
- ❌ 网络文献不写引用日期——链接失效时无法证明"你引用时它存在"
- ❌ 交稿前夜统一改格式——应该在写作第 1 天就定引用制

## 5. 自检与反馈

交稿前逐项打勾：

1. 引用制是否全文统一？→ 混用直接打回
2. 审计脚本 blocker 是否清零？→ 没跑不算做
3. 文内编号与文末条目是否双向对应？→ 单向对应不算（脚本查双向）
4. 抽查的 5+3 条是否全部通过？→ 有一条存疑就扩大抽查
5. 豁免清单是否书面化（含理由）？→ 口头豁免等于没豁免

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的 blocker 全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-lit-review/issues，正文写清"输入 → 错误输出 → 期望输出"。
