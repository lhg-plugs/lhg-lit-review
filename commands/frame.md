# /lhg-lit-review:frame —— 综述框架设计

用户输入在 `$ARGUMENTS` 中：`[文献池文件]`。缺省为当前目录的 `文献池.md`。

## 流程（加载 lhg-lr-frame 全程指导）

### 1. 读文献池
先读文献池的主题标签分布，统计：各标签篇数、年份分布、研究方法分布（实证/理论/综述）。

### 2. 选路线（三选一，不许混搭）
- **主题聚类**：文献观点分歧大、方法多样时用。按"研究问题"分节，每节内部再按观点/方法细分。
- **时间线演进**：领域发展脉络清晰时用。按阶段分节（萌芽→发展→成熟），每节讲清"上一阶段留下了什么未解问题"。
- **学派对比**：存在明确对立阵营时用。按学派分节，专设一节做"交锋点"对比。

把三条路线的 pros/cons 摆给用户，由用户拍板。

### 3. 输出大纲
`综述框架.md` 模板：

```markdown
# 综述框架：<主题>（路线：主题聚类）
## 一、引言（要回答：为什么这个问题值得综述）
## 二、主题A：<名>（文献 L01/L03/L07，要回答：该主题下形成了哪几种观点）
## 三、主题B：<名>（文献 L02/L05，要回答：…）
## 四、批判性述评（要回答：现有研究共识是什么、分歧在哪、方法上有什么短板）
## 五、研究展望（要回答：未来 3-5 年值得做的 3 个方向）
## 附：每节拟引文献对照表
```

### 4. 用户确认
大纲必须经用户确认（增删改节）后才能进入写作。框架不定就动笔，是返工的最大来源。

## 硬规则
- 每节"要回答的问题"不许空着——空着说明这节没想清楚。
- 批判性述评和研究展望是必备节，不许以"文献不够"为由删除；文献不够就写"现有研究尚未回答…"，这本身就是有价值的述评。
- 框架确定后写作中途想改结构，先回这一步更新大纲，保持"大纲-正文"一致。
